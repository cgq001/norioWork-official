# 首页卡片高度与区块间距修正

final result: passed

日期：2026-11-17

## 基准与证据

用户在 `docs/design-evidence/spacious-home-user-markup.png`（2062×1256）标出下半页过于扁平，要求加高。此次以用户的高度修正为优先，不继续追求上一张参考的紧凑总高度。

同一1024×1536 CSS视口、密度1，默认无弹层且FAQ收起：调整前 `extended-home-desktop.jpg`（1024×1537），调整后 `spacious-home-1024.jpg`（1024×2112）。全页变长是本次明确目标，不是密度差异。两者从相同文档坐标y=768裁剪的下半页，以原生像素并排保存为 `spacious-home-comparison.jpg`，已经打开比较；不缩放高度，避免掩盖实际改动。清晰局部证据为 `spacious-home-lower.jpg`。宽屏1448×1086补充为 `spacious-home-desktop.jpg`、`spacious-home-full.jpg`；手机390×844补充为 `spacious-home-mobile-full.jpg`。

## Findings 与修正

- [P2，已解决] 能力、优势、人群、下载与FAQ区域过扁。用户标注与前版截图显示卡片仅76/76/84px，下载区100px，FAQ44px；文字与图标拥挤，区域之间缺少呼吸空间。此次改为能力卡片最小124px、优势126px、人群136px、下载区176px、FAQ66px，增大内边距、网格间距和段落行高；各内容区增加约28–38px上下留白。1448px实测能力卡片约126px，其他区域符合设定；1024px按换行自动增加高度，无硬性裁切。
- 修正后同图比较及宽屏实机截图已确认，未发现剩余P0/P1/P2问题。手机与320px边界没有全页或卡片局部横向溢出。

## 五项必检表面

1. **字体**：保持原系统字体栈、区块标题与导航；能力标题增至18/26px，正文14/23px，优势/人群标题16/24px、正文13/22px；窄屏分级缩小，中文自然换行，没有截断。
2. **间距与布局**：保持原来的列数与内容顺序，扩大卡片内边距、卡片间距和区块上下距离；手机卡片同步加高，不出现文字贴边或图标重叠。全页变长约575px（1024px宽）。
3. **颜色**：沿用蓝白背景、原按钮与卡片颜色、轮廓和阴影，没有新增配色偏移。
4. **图片**：沿用已验收资源。人群头像放大后仍使用object-fit:contain，下载机器人保持原比例；没有拉伸图片或新造视觉占位物。
5. **文案**：内容、下载地址、平台待发布说明均未变；只调整排版高度和文字可读性。

## 验证

- 浏览器检查320、390、1024、1448px无全页横向溢出；能力、优势、人群、系统选项、FAQ均无局部水平溢出。
- 手机和宽屏截图已打开检查；FAQ展开后不越界，点击可收起。
- `npm run check`、`npm run build`、`git diff --check`通过。
- 仅修改首页CSS与设计记录，沿用已有详情弹层和GitCode固定最新版入口；无需新增测试或接口。
- 本地预览保持运行且页面保留，未部署。
